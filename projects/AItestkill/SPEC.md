## 2. 핵심 게임 규칙

### 2.1 진행 흐름

1. 시작 화면에서 플레이어의 학번(`studentId`)을 입력하고 게임을 시작한다.
2. 3D 고사장에 수험생 30명(5열 x 6행)이 배치되며, 이 중 부정행위자 다수(기본 8명)가 무작위 좌석과 유형으로 배정된다.
3. 시험 시작과 함께 제한 시간 타이머가 감소하며, 부정행위자들은 주기적으로 부정행위 동작(활성 상태)과 일반 풀이 동작(대기 상태)을 오간다.
4. 감독관은 복도를 자유롭게 걸어 다니며 눈으로 단서를 관찰하고 화면 가장자리 흐림 효과로 미세 소음 방향을 추적하여 의심 수험생을 적발한다.
5. 종료 조건(제한 시간 만료, 부정행위자 전원 검거, 또는 하트 3개 모두 소진)에 도달하면 최종 점수를 산출하고 학번과 함께 서버 및 외부 DB 커넥터로 전송한다.

### 2.2 체력(HP) 및 적발 판정

| 항목 | 내용 |
|---|---|
| 초기 체력 | 하트 3개 |
| 적발 조건 | 3.6m 이내의 미판정 수험생을 우클릭 집중 응시로 0.5초 이상 조준 고정한 뒤 `E` 키로 적발 (미충족 시 하트 차감 없이 안내 문구 출력) |
| 정당 적발 | 부정행위자를 적발하면 해당 수험생은 퇴장 처리되고 기본 점수, 속도 보너스, 콤보 배율이 가산되며 핵심 단서 사유가 표시됨 |
| 오심(잘못된 적발) | 일반 수험생을 적발하면 하트 1개 차감, 연속 검거 콤보 초기화, 오심 감점 적용 및 결백 사유가 표시됨 |
| 체력 소진 | 하트가 0개가 되면 즉시 시험 감독 실패로 종료되며 그때까지 획득한 점수로 정산 기록됨 |
| 동시 발동 템포 | 부정행위자 2~3명이 교차로 활성 상태에 진입하며 일반 수험생 함정 동작도 함께 발생함 |

### 2.3 점수 산정 공식

| 항목 | 계산식 및 수치 |
|---|---|
| 기본 검거 점수 | 기기 난이도에 따라 1,000점 ~ 1,400점 |
| 신속 검거 보너스 | 부정행위 첫 단서 노출 후 검거까지 걸린 시간(`t`초) 기준 `max(0, 500 - floor(t * 15))`점 |
| 연속 검거 배율 | 오심 없이 연속 검거 시 1콤보 `1.0x`, 2콤보 `1.2x`, 3콤보 `1.4x`, 4콤보 이상 `1.6x` (기본 점수에 적용) |
| 조기 완수 보너스 | 부정행위자 전원 검거 시 남은 시험 시간(초) x 30점 |
| 잔여 하트 보너스 | 시험 정상 종료 시 남은 하트 개수 x 300점 |
| 오심 감점 | 1회당 -500점 (총점 하한선 0점) |

## 3. 수험생 패턴 설계

### 3.1 부정행위자 유형 (4종) 및 3단계 범행 사이클

부정행위자 8명은 4종 유형에 각 2명씩 배정되며, `촬영 조준(2.6초) -> AI 응답 수신(3.0초) -> OMR 급속 마킹(2.6초) -> 위장 휴식(5.2~7.0초)` 순서의 3단계 범행 사이클을 교차 수행한다.

| 유형 | 장착 기기 | 3단계 행동 및 시각 단서 | 소음 단서 (화면 좌/우 흐림 유발) | 상시 물리 물증 및 보조 도구 |
|---|---|---|---|---|
| 촬영 LED AI안경 + 쌀알이어폰 | 전면 모서리 촬영 LED 안경 + 귓속 이어피스 | 상체를 세우고 관자놀이를 누를 때 안경 모서리 백색 촬영 LED 2회 점멸, 이어 귓구멍을 눌러 수신 후 OMR만 마킹 | 수신 단계에서 고주파 전자 진동 유발 | 풀이 없는 백지 문제지 + OMR 마킹, 전파 강함, 스팟 라이트 점 반사 |
| 안경 바꿔치기 HUD 스마트안경 | 두꺼운 뿔테 HUD 안경 + 교체용 일반 안경 | 책상 아래로 손을 내렸다 올리며 두꺼운 스마트안경으로 교체하고 여분 안경을 책상 좌상단에 둠, 렌즈 내측 청록색 HUD 광원 | 안경다리 터치 스와이프 시 약한 전자음 | 책상 위 여분 안경 + 백지 문제지 + OMR 마킹, 전파 중간 |
| 단추 카메라 + 책상 밑 송신기 | 셔츠 두 번째 단추 렌즈 + 책상 밑 송신기 | 왼손을 책상 아래 허벅지 위치로 내려 송신기를 누르고 오른손으로 옷깃을 고정, 수신 시 헛기침·속삭임 발생 | 수신 단계에서 헛기침/속삭임 파동 유발 | 돌출된 2번째 단추 광학 렌즈 + 백지 문제지, 스팟 라이트 점 반사 |
| 볼펜 스캐너 카메라 | 클립 내장 스캐너 펜 | 필기 대신 문제지 줄을 따라 일정 속도로 수평 스캔하며 청색 스캔선 표시, 완료 후 OMR만 마킹 | 스캔 클릭 및 구동 진동 유발 | 펜 클립 상단 원형 렌즈 + 백지 문제지, 스팟 라이트 점 반사 |

### 3.2 일반 수험생 배분 및 함정 패턴

- 일반 집중 응시생(15명): 상체를 앞으로 숙이고 양손을 책상 위에 둔 채 문제지 여백에 정상 풀이 과정을 작성하며 간헐적으로 OMR을 기입한다.
- 일반 함정 응시생(7명): 부정행위자와 구별하기 위해 교차 검증이 필요한 결백 행동이 간헐적으로 발생한다.

| 함정 유형 | 행동 묘사 | 부정행위와의 구별 포인트 (결백 근거) |
|---|---|---|
| 일반 도수 안경 착용자 | 흘러내린 얇은 안경 코받침을 검지로 밀어 올림 | 백색 촬영 LED·HUD 투영광 없음, 문제지에 정상 풀이 과정 존재 |
| 볼펜 딸깍이 응시생 | 초조하게 볼펜 노크를 연속으로 누름 | 좌/우 소음 흐림은 유발하나 문제지 정상 풀이 중이며 전자기기·전파 신호 없음 |
| 금속 안경테·시계 착용자 | 일반 금속테 안경이나 손목시계를 자주 확인함 | 스팟 라이트 조사 시 둔탁한 표면 반사만 일어나며 문제지 정상 풀이 확인 가능 |
| 암산형 일반 응시생 | 턱을 괴고 허공을 보며 암산하여 문제지 여백 풀이가 적음 | 문제지 필기는 적으나 스마트안경, 책상 밑 손, 촬영 LED, 전파 신호가 전혀 없음 |

### 3.3 감독관 접근 경계 및 움찔(Flinch) 반응

- 감독관이 빠른 걸음(`Shift`)으로 접근하거나 정면 2.2m 이내에서 주시하면, 촬영 또는 수신 중인 부정행위자가 화들짝 어깨를 떨며 손을 빼는 움찔(`alert_flinch`) 동작 후 위장 휴식(`alert_hiding`)에 들어간다.
- 안경 바꿔치기 유형은 움찔 시 두꺼운 스마트안경을 벗어 책상 모서리에 급히 내려놓으므로, 이미 책상에 놓인 여분 스마트안경과 백지 문제지·OMR 기록으로 사후 적발이 가능하다.

## 4. 감독관 조작, 신체 감각, 보조 도구

### 4.1 조작 체계 (1인칭 자유 이동)

| 입력 | 동작 | 설명 |
|---|---|---|
| `W`, `A`, `S`, `D` | 복도 이동 | 책상 사이 통로 및 교탁 주변 1인칭 이동 |
| `Shift` (홀드) | 빠른 이동 | 이동 속도 1.5배 증가, 주변 수험생 경계도 상승 |
| 마우스 이동 | 시선 회전 | Pointer Lock 기반 1인칭 시점 회전 |
| 마우스 우클릭 (홀드) | 집중 응시 (시력) | 시야 확대(FOV 축소), 조준 대상의 안경/단추/손 미세 단서 선명화 |
| `Space` (홀드) | 집중 청음 (청력) | 이동 속도 감소, 소음 감지 반경 확대 및 좌/우 화면 흐림 방향 정밀도 상승 |
| 숫자키 `1` | 전파 감지기 토글 | 보조 도구 1 장착/해제 |
| 숫자키 `2` | 광학 스팟 라이트 토글 | 보조 도구 2 장착/해제 |
| 마우스 좌클릭 | 보조 도구 작동 | 스팟 라이트 장착 시 전방 순간 조사 |
| `E` | 부정행위 적발 | 3.6m 이내 대상을 우클릭 0.5초 고정 후 적발 판정 |
| `F9` | 부스 운영자 리셋 | 점수를 저장하지 않고 즉시 초기 화면으로 초기화 |

### 4.2 무음 환경 대응 청각 시각화 시스템 (Directional Blur HUD)

현장 플레이 환경에서 스피커나 헤드폰을 사용하지 못하는 상황을 기본 기준으로 삼아 모든 소음 단서를 시각 효과로 변환한다. (선택적 Web Audio 효과음은 별도 음소거 토글로만 제공하며 게임 진행에 필수적이지 않다.)

1. 상시 감지 및 방향 계산:
   - 매 프레임 감독관의 카메라 위치와 정면 벡터, 우측 벡터를 기준으로 소음을 발생시키는 수험생까지의 거리(`d`)와 좌우 내적값(`pan = dot(rightVector, dirToStudent)`), 전후 내적값을 계산한다.
2. 화면 좌/우 가장자리 뿌연 흐림 연출:
   - 좌측에서 소음이 나면 화면 왼쪽 가장자리, 우측에서 소음이 나면 화면 오른쪽 가장자리에 반투명 안개 및 블러(`backdrop-filter: blur(...)` + 그라데이션 비네팅 파동) 레이어가 생성된다.
   - 소음 발생원과의 거리가 가까울수록 흐림 영역의 폭과 불투명도가 강해지고 미세한 맥동 주기가 빨라진다.
   - 정면에 가까워지면 좌측과 우측 상단 가장자리가 균등하게 옅은 파동을 보이며 방향이 맞았음을 알려준다.
3. 집중 청음(`Space` 홀드) 보정:
   - 감지 반경이 기본 4.5m에서 7.5m로 확장되고, 수험생의 소음 유형(미세 진동 계열 vs 속삭임/딸깍임 계열)에 따라 흐림 파동의 번짐 주기가 다르게 표현되어 방향 추적을 돕는다.

### 4.3 보조 도구 상세 (힌트 전용)

1. 전파/통신 감지기 (보조 도구 1):
   - 화면 우하단 소형 단말기 게이지로 감독관 반경 3.8m 내 무선 패킷 세기를 0~3칸으로만 표시한다.
   - 특정 좌석이나 방향은 표시하지 않는다. 반경 안에 수험생이 여러 명 포함되므로 신호가 잡히면 감독관이 직접 근처 수험생들의 안경, 손, 옷깃을 눈으로 확인해야 한다.
   - 연속 가동 시 배터리 게이지가 서서히 소모되며 비활성화 시 자동 충전된다.
2. 광학 스팟 라이트 (보조 도구 2):
   - 좌클릭 시 1.2초 동안 전방 좁은 각도로 조사광을 비추며, 카메라 핀홀 렌즈에 닿을 경우 0.35초간 날카로운 청백색 렌즈 반사점(Glint)을 발생시킨다.
   - 1회 사용 시 배터리 35%를 소모하고 3초 쿨타임이 적용된다.
   - 일반 금속 안경테나 손목시계에서도 둔탁한 백색 반사가 발생하도록 설계하여, 반사만 보고 바로 적발하면 오심 위험이 따르도록 제한한다. 반드시 집중 응시로 실제 기기 형태를 확인해야 한다.

## 5. 시스템 아키텍처 및 스코어보드 연동 설계

### 5.1 기술 스택

- 프론트엔드: Vite, React, TypeScript, Three.js, Zustand
- 백엔드: Node.js, Express, TypeScript (`tsx` 개발 구동 및 `tsc` 빌드 구동)
- 운영체제 호환 원칙:
  - OS 종속 쉘 문법(`rm -rf`, 경로 구분자 하드코딩 등)을 배제하고 Node.js 표준 `path`, `fs/promises` 모듈과 크로스플랫폼 스크립트를 사용한다.
  - 네이티브 C++ 컴파일이 필요한 패키지를 사용하지 않아 Windows와 macOS에서 `npm install`만으로 동일하게 실행된다.

### 5.3 DB Connector 및 전광판 PC 연동 규격

추후 스코어 표시 전용 컴퓨터나 외부 DB에 학번과 점수를 내보내기 위해 저장 계층을 `DbConnector` 인터페이스로 분리한다.

```typescript
export interface ScoreRecord {
  id: string;
  studentId: string;
  score: number;
  caughtCount: number;
  totalCheaters: number;
  wrongCatchCount: number;
  remainingHearts: number;
  elapsedSeconds: number;
  clearedAll: boolean;
  createdAt: string;
}

export interface DbConnector {
  init(): Promise<void>;
  saveScore(record: ScoreRecord): Promise<void>;
  getTopScores(limit: number): Promise<ScoreRecord[]>;
  getRecentScores(limit: number): Promise<ScoreRecord[]>;
  healthCheck(): Promise<{ ok: boolean; mode: string }>;
}
```

- 기본 구동 모드(`DB_CONNECTOR=json`): 별도 DB 서버 없이 `data/scores.json`에 즉시 기록하며, 같은 네트워크의 전광판 컴퓨터에서 `http://<게임PC_IP>:3001/?view=board`로 접속하면 SSE(`GET /api/scores/stream`)를 통해 방금 끝난 플레이어의 학번과 점수가 실시간으로 갱신된다.
- 외부 DB / 외부 스코어 서버 연동 모드(`DB_CONNECTOR=webhook` 또는 `DB_CONNECTOR=sql`): `.env` 파일에 외부 DB 접속 정보 또는 스코어보드 수신 URL만 설정하면 게임 코드 수정 없이 `studentId`와 `score` 데이터가 외부 시스템으로 즉시 전송된다.

### 5.4 백엔드 API 명세

| 메서드 | 경로 | 설명 |
|---|---|---|
| `GET` | `/api/health` | 서버 구동 상태 및 활성 DB 커넥터 종류 반환 |
| `POST` | `/api/scores` | 게임 종료 시 `studentId`, `score` 및 세부 플레이 지표 검증 후 저장 및 브로드캐스트 |
| `GET` | `/api/scores/leaderboard?limit=20` | 학번당 최고 점수 1건 기준으로 정렬된 상위 순위 반환 |
| `GET` | `/api/scores/recent?limit=10` | 최근 완료된 플레이 기록 반환 |
| `GET` | `/api/scores/stream` | Server-Sent Events 기반 전광판 실시간 업데이트 스트림 |

## 6. 3D 고사장 시각 구성 (Three.js)

- 프로시저럴 3D 모델링 기반으로 외부 대용량 에셋 의존 없이 즉시 로드되도록 구현한다.
- 고사장 공간: 전면 칠판과 디지털 시계, 교탁, 5열 6행 책상과 의자, 창문 채광, 천장 조명 배치.
- 책상 물증 구성: 각 책상 위에 우측 OMR 답안 카드(진행에 따라 검은 마킹이 5문항 단위로 채워짐)와 좌측 백색 문제지(정상 풀이 필기형 / 암산 소량 필기형 / 풀이 흔적이 전혀 없는 백지형)를 분리 배치한다.
- 수험생 표현: 허리 상체 관절(`upperBodyGroup`), 머리, 양팔(책상 밑 송신 동작 및 귀/안경 접촉 가능), 백색 촬영 LED·여분 교체 안경·2번째 단추 렌즈·스캐너 펜을 구분 가능한 지오메트리와 머티리얼로 구성한다.
- 거리별 가시성 제어: 복도 원거리에서는 자세·상체 움직임과 백색 LED 점멸 등으로 1차 의심 대상을 좁히고, 근접하여 우클릭 집중 응시(`FOV 25` 확대)를 수행할 때 문제지 풀이 유무, OMR 마킹, 기기 외형 단서가 선명하게 드러나도록 처리한다.
